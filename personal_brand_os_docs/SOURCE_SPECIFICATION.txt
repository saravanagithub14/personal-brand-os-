PROJECT: Personal Brand OS
TYPE: Django-based AI-powered personal brand management platform

You are a senior full-stack engineer, Django architect, AI engineer, product designer, and DevOps engineer.

Build a production-quality web application called:

"Personal Brand OS"

The application is a single dashboard for managing my entire personal brand across multiple social media platforms.

The system must combine:

1. Social media content calendar
2. AI content preparation
3. AI script generation
4. AI content repurposing
5. News and research scraper
6. Personal brand knowledge base
7. Content idea management
8. Content approval workflow
9. Publishing/scheduling architecture
10. Content analytics
11. Project and portfolio management
12. Personal brand dashboard
13. AI agents for different content tasks

The application must be modular and designed so additional social platforms, AI providers, scrapers, and agents can be added later.

==================================================
PHASE 0: PRODUCT PRINCIPLES
==================================================

Do NOT build a simple CRUD dashboard.

Build an actual personal brand operating system.

The application should answer:

"What should I post?"

"Why should I post it?"

"Where should I post it?"

"When should I post it?"

"How should I present it?"

"Can this idea be repurposed?"

"What news is relevant to my niche?"

"What content is performing?"

"What should I create next?"

The AI should assist me, but I must remain in control.

Every AI-generated item should be editable before publication.

Never automatically publish AI-generated content without an explicit approval state.

==================================================
IMPORTANT DEVELOPMENT RULES
==================================================

1. Do not build everything in one giant file.

2. Follow Django conventions.

3. Use reusable services.

4. Use type hints where useful.

5. Add docstrings to complex services.

6. Avoid duplicated code.

7. Do not fake API integrations.

8. If a social API is unavailable, implement a clean mock adapter.

9. Never fabricate analytics.

10. Never fabricate personal achievements.

11. AI-generated content must always be editable.

12. Human approval is required before publishing.

13. Keep AI provider abstraction separate from business logic.

14. Keep social platform integrations separate from content logic.

15. Keep scraping separate from AI processing.

16. Keep analytics separate from publishing.

17. Use database transactions where appropriate.

18. Add logging for background jobs.

19. Handle failed Celery jobs gracefully.

20. Make the system easy to extend.
